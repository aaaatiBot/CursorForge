# Windows Cursor Subsystem & Engine Documentation

## 1. Overview

The Windows cursor engine in CursorForge manages the live application of mouse cursor schemes directly into the Windows operating system. It interfaces with the Windows Registry and user32 API while providing atomic rollback, dynamic system default resolution, and multi-DPI binary `.cur` compilation.

---

## 2. Windows Cursor Roles

Windows standardizes 15 primary cursor roles. CursorForge models each role in `Models/CursorRoleDefinition.cs`:

|---|---|---|---|---|---|
| 1 | `Arrow` | `Arrow` | Normal Select | 32×32 .. 128×128 | Primary pointer arrow |

| 3 | `AppStarting` | `AppStarting` | Working in Background | 32×32 .. 128×128 | Arrow with spinner/hourglass |
| 4 | `Wait` | `Wait` | Busy | 32×32 .. 128×128 | Continuous spinner / hourglass |
| 5 | `Crosshair` | `Crosshair` | Precision Select | 32×32 .. 128×128 | Centered crosshair `+` |
| 6 | `IBeam` | `IBeam` | Text Select | 32×32 .. 128×128 | Vertical text insertion caret |
| 7 | `NWSE` | `SizeNWSE` | Diagonal Resize 1 | 32×32 .. 128×128 | Top-left to bottom-right `\` |

## 3. Registry Architecture

### 3.1 Active Cursor Scheme
Active cursor paths are located at:
```
HKEY_CURRENT_USER\Control Panel\Cursors
```
- Type: `REG_SZ` or `REG_EXPAND_SZ` (e.g. `%SYSTEMROOT%\cursors\aero_arrow.cur`).
- An empty string `""` instructs Windows to use its compiled-in kernel default cursor for that role.

### 3.2 Registered Schemes
Schemes are registered at:
```
HKEY_CURRENT_USER\Control Panel\Cursors\Schemes
```
Values are formatted as a comma-separated list of 15 paths matching the standard role order. When a user creates or installs a theme, CursorForge registers the theme in this registry key so it appears in standard Windows settings dialogs.

## 4. Win32 API Contract & Reload Mechanism

Modifying registry values alone does not update cursors immediately on the user's desktop. To signal the Windows desktop window manager:

```csharp
[DllImport("user32.dll", SetLastError = true, CharSet = CharSet.Auto)]
private static extern bool SystemParametersInfo(
    uint uiAction,
    uint uiParam,
    IntPtr pvParam,
    uint fWinIni
);

private const uint SPI_SETCURSORS = 0x0057;
private const uint SPIF_UPDATEINIFILE = 0x01;
private const uint SPIF_SENDCHANGE = 0x02;
```

### Headless / Background Test Runner Handling
In non-interactive sessions or CI test agents without an active desktop window manager, `SystemParametersInfo` returns `FALSE` but `Marshal.GetLastWin32Error()` reports `0` (`ERROR_SUCCESS`). 

CursorForge explicitly checks:
```csharp
if (!success)
{
    int error = Marshal.GetLastWin32Error();
    if (error != 0)
    {
        throw new Win32Exception(error, $"Failed to reload system cursors (SPI_SETCURSORS error {error})");
    }
}
```
This guarantees rock-solid reliability both on user workstations and in CI/CD automation pipelines.

## 5. Binary `.cur` Encoding Rules

Windows `.cur` files generated by `CursorConverterService` adhere to the Microsoft Icon/Cursor format specification:

1. **Header (ICONDIR)**:
   - `idReserved`: `0`
   - `idType`: `2` (Cursor; 1 is for Icon)
   - `idCount`: `5` (Multi-size: 32, 48, 64, 96, 128 px)

2. **Directory Entries (ICONDIRENTRY)**:
   - Width and height (byte, where `128` is encoded as `128` or `0` for 256).
   - Hotspot coordinates `wXHotspot`, `wYHotspot` (16-bit words) scaled proportionally:
     $$\text{Hotspot}_{\text{tier}} = \text{round}\left(\text{Hotspot}_{\text{base}} \times \frac{\text{TierSize}}{\text{BaseSize}}\right)$$
   - Payload byte count and absolute file offset.

3. **DIB Header (BITMAPINFOHEADER)**:
   - `biSize`: 40 bytes.
   - `biWidth`: Tier width.
   - `biHeight`: Tier height $\times 2$ (representing both XOR color mask and AND 1-bit mask).
   - `biPlanes`: 1.
   - `biBitCount`: 32.
   - `biCompression`: 0 (`BI_RGB`).

4. **Mask Construction**:
   - **XOR Mask**: 32-bit BGRA bytes in bottom-up row order. Colors must have premultiplied alpha:
     $$B = \frac{B_{\text{orig}} \times A}{255}, \quad G = \frac{G_{\text{orig}} \times A}{255}, \quad R = \frac{R_{\text{orig}} \times A}{255}$$
   - **AND Mask**: 1 bit per pixel (0 = opaque, 1 = transparent). Scanlines padded to 4-byte boundaries.

5. **Validation**:
   Every generated `.cur` is verified via Win32 `LoadCursorFromFileW` and `GetIconInfo` to ensure the Windows operating system will load the file without crashing the shell.
